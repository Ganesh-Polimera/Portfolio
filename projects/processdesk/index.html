PROJECT 01 / POWER PLATFORM IMPLEMENTATION KIT

ProcessDesk

Guided intake, clear ownership, and a traceable approval decision.

Open interactive demo ↗Native build guide ↓

What exists today: a working JavaScript browser prototype, tested workflow logic, Canvas app property formulas, a SharePoint schema script, and a detailed cloud-flow build guide. Native Power Apps and Power Automate deployment requires a sandbox build and UAT.

The problem

Requests arriving through email often miss the business context, go to the wrong reviewer, and lose their decision history. Teams need one intake and an accountable next step.

The solution

ProcessDesk routes requests using three explicit categories. Reviewers approve or reject; expired approvals move to manual review. Every browser action adds a timestamped history event, and decisions cannot be applied twice.

What you can try

  1. Submit an Access, Collaboration, or Automation request.
  2. Find it in the queue and check the assigned reviewer.
  3. Try approving it, rejecting with a reason, or simulating an approval timeout.
  4. Inspect its history, filter the queue, and download the CSV.

The engineering choices

  • Separate intake from decisions. A hidden field is not an authorization boundary. Native decision records belong in a restricted list.
  • Use a unique request key. Duplicate trigger deliveries must not create duplicate approvals.
  • Make timeouts explicit. The native guide uses a seven-day wait and manual reconciliation of outstanding approvals.
  • Validate before scaling. Test with two requester identities, reviewer identities, duplicate events, and notification failures.

Where AI could help

An optional next step is a human-reviewed category suggestion through an approved AI service. It should suggest a route, allow an override, and never grant access or approve a request. No AI service is connected in this delivery.

Success measures

After a tenant pilot, measure routing accuracy, decision turnaround, reopened requests, and exception rate against a documented baseline. No production time-savings or adoption figures are claimed for this prototype.
