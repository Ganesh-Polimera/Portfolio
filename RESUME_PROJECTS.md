# Resume project language and interview preparation

Use statements that match what you can demonstrate. The current delivery is a browser prototype, implementation kit and working comparison utility. It is not evidence of a native tenant deployment.

## Accurate to this delivery

**ProcessDesk — Request Intake & Approval Prototype | Portfolio Project**
- Developed an interactive request-management prototype with category-based reviewer routing, approval and rejection transitions, timeout escalation, and timestamped decision history.
- Prepared a Power Apps and Power Automate implementation kit covering Canvas form formulas, SharePoint list schemas, unique request keys, restricted approval state, failure handling, and UAT scenarios.

**Migration Assurance — SharePoint Inventory Validation | Portfolio Project**
- Built a browser and Node.js utility to compare mapped source and destination inventories, flag missing or additional lists and count discrepancies, and export exception reports for review.
- Added input validation and automated tests for duplicate keys, zero counts, destination surpluses and malformed records, with a read-only PnP PowerShell export script for sandbox validation.

## Use only after native implementation and UAT

**ProcessDesk — Power Apps & Power Automate Request Management | Portfolio Project**
- Built a Canvas app backed by SharePoint Lists with category-based Power Automate approvals, requester notifications, and a restricted decision record.
- Implemented unique request keys, approval timeouts, exception notifications, and documented UAT covering duplicate events, authorization and failed notifications.

Do not use the second set until you have built and tested those exact native behaviors. Replace general claims with measured results only after a pilot establishes a baseline and sample size. Keep portfolio projects separate from paid employment experience.

## Five-minute interview demo

1. Explain the manual process and the person affected (30 seconds).
2. Submit a ProcessDesk request and show its reviewer route (60 seconds).
3. Make a decision or demonstrate a timeout and show history (60 seconds).
4. Explain why native intake and authoritative approval state are separated, and how a unique key prevents duplicate approvals (60 seconds).
5. Run the synthetic inventory comparison and explain why a count match is not sufficient for migration sign-off (60 seconds).
6. State exactly what is implemented, what requires a Microsoft environment, and the next test you would run (30 seconds).
